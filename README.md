# 학생명단 관리 시스템

**초등학교** 학생명단을 한 곳에서 관리하는 Windows 프로그램입니다.
학생정보를 한 번만 등록하면 검색·전입·전출·형제 탐색·주소 분류·통계·진급·명단 생성을 프로그램이 처리합니다.

> 자료는 **이 컴퓨터 안에만** 저장됩니다. 외부 서버나 AI 서비스로 보내지 않습니다.

두 가지 원칙으로 만듭니다.

- 학생정보는 한 번만 입력하고, 필요한 명단은 프로그램이 만든다.
- 원본 데이터는 보존하고, 시스템이 정리한 값을 따로 둔다.

설계와 진행 계획은 [docs/01-설계안.md](docs/01-설계안.md),
설치·백업·복원·업데이트 안내는 [docs/02-운영안내.md](docs/02-운영안내.md)에 있습니다.

---

## 설치와 자료

1. 릴리스 페이지에서 `student-roster_…_x64-setup.exe` (가장 최신 것)를 내려받아 실행합니다.
   **관리자 권한이 필요 없습니다.** Windows가 "PC를 보호했습니다" 창을 띄우면
   **추가 정보 → 실행**을 누르세요(코드 서명 인증서가 없는 프로그램은 모두 그렇습니다).
2. 시작 메뉴의 **학생명단 관리 시스템**으로 엽니다.
3. 첫 실행 화면에서 학교 이름과 현재 학년도를 넣으면 바로 쓸 수 있습니다.

**학생 자료는 프로그램과 따로 보관됩니다.**

```
%APPDATA%kr.school.studentroster  studentroster.db     학생 자료 (이 파일 하나)
  backups             백업 파일
```

- 자료는 **이 컴퓨터 안에만** 있습니다. 외부 서버·AI 서비스로 보내지 않습니다.
- 프로그램을 **업데이트하거나 지웠다 다시 깔아도 자료는 그대로** 남습니다.
  프로그램을 지워도 위 폴더는 지워지지 않습니다(없애려면 직접 지워야 합니다).
- 개인정보가 들어 있는 파일이므로 Windows 계정에 암호를 걸고, 가능하면
  BitLocker(드라이브 암호화)를 켜 두세요.

### 백업 · 복원 · 업데이트 한 줄 요약

| 하고 싶은 일 | 어디서 |
|---|---|
| 지금 자료를 백업 | 설정 → 백업 → **[지금 백업]** |
| 백업 파일 보기·USB로 옮기기 | 설정 → 백업 → **[백업 관리]** · **[백업 폴더 열기]** |
| 예전 자료로 되돌리기 | 설정 → **백업에서 복원** → 백업을 고르고 [되돌리기] → [프로그램 종료] → 다시 실행 |
| 새 버전 받기 | 설정 → 프로그램 업데이트 → **[업데이트 확인]** |

- 자동 백업은 **하루에 한 번**, 최근 30개까지 둡니다. 직접 만든 백업과 학년도 전환 전·
  복원 전 백업은 자동으로 지우지 않습니다.
- 백업은 만든 뒤 **다시 열어 확인**합니다. 확인에 실패한 파일은 정상으로 표시하지 않습니다.
- 복원은 **되돌리기 직전에 지금 자료를 한 번 더 백업**(`before_restore_…`)하므로,
  고른 백업이 생각과 달랐어도 되돌아올 수 있습니다.
- ⚠️ **백업 파일에는 학생 개인정보가 그대로 들어 있습니다.** 옮겨 둔 저장장치의 보관에
  주의해 주세요.

자세한 내용은 [docs/02-운영안내.md](docs/02-운영안내.md)를 보세요.

## 지금 할 수 있는 것

- **학생 등록·수정** — 학년/반/번호 · 이름 · 성별 · 생년월일 · 주소 · 보호자 · 비고.
  반 이름은 `1` 도 `가람` 도 됩니다.
- **생년월일 정규화** — `170315` `17.03.15.` `17-03-15` `2017.03.15` 을 모두 같은 날짜로 읽고
  화면에는 `17.03.15.` 로 보여 줍니다. 달력에 없는 날짜는 **고치지 않고** 원본을 그대로 둔 채
  확인 필요로 표시합니다.
- **연락처 부분 검색** — `010-1234-5678` 을 `1234` 로도 `5678` 로도 찾습니다.
- **학생명단** — 학년·반·상태로 추리고, 검색 한 칸에서 이름·연락처·주소·번호를 함께 찾습니다.
  항목별로 따로 찾고 싶으면 [상세 검색]을 엽니다.
- **오류가 있어도 막지 않는다** — 빠진 값이 있어도 등록은 그대로 되고 표시만 남습니다.
  값을 채워 저장하면 표시가 저절로 사라집니다.
- **학적 이력** — 학년도별 학적과 이동 기록(등록·전입·전출·진급·졸업)을 학생마다 보관합니다.
  지난 학년도 기록은 덮어쓰지 않습니다.
- **엑셀 명단 가져오기** — 파일을 고르면 열 이름을 알아서 짝지어 줍니다(성명·학급·출석번호 등).
  **저장하기 전에** 무엇이 새로 들어가고 무엇이 어떻게 바뀌는지 보여 줍니다.
  같은 파일을 다시 넣어도 학생이 두 벌로 쌓이지 않고, 엑셀 빈칸이 기존 값을 지우지 않습니다.
- **주소 분류** — 주소에서 `도로명 건물번호` 를 뽑아 동·호수가 달라도 같은 건물로 묶습니다.
  주소에 단지 이름이 적혀 있으면 저절로 분류하고, 애매하면 **추측하지 않고** 확인을 요청합니다.
  한 학생을 확인하면서 만든 규칙을 같은 주소의 다른 학생에게 한 번에 적용할 수 있습니다.
  직접 지정한 분류는 자동 재적용이 건드리지 않습니다.
- **본교 형제 찾기** — 보호자 성명·연락처 가운데 **값이 있는 항목이 두 가지 이상** 같은 학생을
  형제 후보로 보여 줍니다. 빈칸끼리는 같다고 보지 않고, 비슷한 이름을 묶지도 않습니다.
  무엇이 같아서 후보가 되었는지 항목별로 보여 주므로 보고 나서 판단할 수 있습니다.
  **형제 아님으로 정한 관계는 다시 묻지 않습니다.**
- **형제 후보 한꺼번에 확정** — 확인 필요 화면에서 [형제 후보] 를 누르면 후보가 쌍마다
  한 줄로 나옵니다. 처음에는 모두 골라져 있고, 아닌 쌍만 체크를 풀어 **[선택한 N건
  형제로 확정]** 을 한 번 누르면 끝납니다. 확정 전에 몇 건인지 다시 묻고, 확정은
  한 번에 처리되므로 **절반만 형제가 되는 일이 없습니다.** 확정하면 보호자 정보
  보완·불일치 확인이 이어서 계산되고 후보 표시는 사라집니다.
- **보호자 정보 보완** — 형제로 확인한 뒤, 형제에게는 있고 이 학생에게는 없는 보호자 정보를
  알려 줍니다. 원하는 항목만 골라 가져올 수 있고, **빈칸만 채우며 이미 있는 값은 덮어쓰지 않습니다.**
  서로 값이 다르면 양쪽을 나란히 보여 주기만 하고 프로그램이 고르지 않습니다.
- **확인 필요 업무함** — 주소·생년월일·보호자·형제·번호 등 확인할 것을 한 화면에 모읍니다.
  종류별 건수를 눌러 추리고, 학년·반·미해결 여부로 좁히고, `3-나리 홍길동` 처럼 찾을 수 있습니다.
  한 줄을 누르면 그 자리에서 고칠 수 있는 칸이 바로 열리고, **값을 고치면 표시가 저절로
  사라집니다.** 눌러서 덮어 두는 [해결] 버튼은 없습니다. 지난 항목은 [해결됨]으로 볼 수 있습니다.
- **학생 번호 재정렬** — 23번을 7번으로 옮기면 7~22번이 한 칸씩 밀립니다.
  **바꾸기 전에 누구의 번호가 어떻게 되는지 표로 보여 주고**, [번호 이동]을 눌러야 저장합니다.
  같은 학년·반 학생만 움직이고, `1,2,3,5,6,9` 처럼 띄엄띄엄한 반을 억지로 1번부터 다시
  매기지 않습니다. 번호가 겹친 반에서는 어느 쪽을 밀어야 할지 알 수 없으므로 멈추고 알려 줍니다.
- **형제 표시는 늘 최신** — 이름표를 저장하지 않고 볼 때마다 지금 학적으로 만들기 때문에
  형제가 진급하거나 반이 바뀌어도 표시가 저절로 맞습니다.

- **전입 처리** — 먼저 이미 등록된 학생인지 찾습니다. 지난 학년도에 다녔거나 올해
  전출했던 학생이면 **그 학생을 그대로** 써서 기록이 이어집니다. 이름이 같다고 프로그램이
  같은 학생이라고 정하지 않고, 지난 학적을 보여 주고 사람이 고릅니다.
  학년을 고르면 **반별 남/여/미입력 인원**과 반을 고른 뒤의 예상 인원을 보여 줍니다.
  어느 반이 좋은지는 권하지 않습니다.
- **전출 처리** — 학생 자료를 지우지 않고 현재 명단에서만 뺍니다. 바꾸기 전에 지금
  학적과 날짜를 보여 주고 한 번 더 묻습니다. 잘못 눌렀으면 **전출 취소**로 되돌릴 수
  있고, 전출했던 기록과 되돌린 기록이 모두 학적 이력에 남습니다.
- **같은 학년도에 나갔다 돌아와도** 학적이 두 줄이 되지 않습니다. 있던 학적을 되살리고
  나간 기록은 그대로 남깁니다.
- **지난 전출생 추가** — 프로그램을 쓰기 전에 이미 떠난 학생을 명단에 넣었다 빼는 번거로운
  길 없이 바로 전출 기록으로 넣습니다.

- **통계** — 전체 · 학년별 · 학년×반×성별 · 주소 분류×학년을 표로 봅니다.
  **학생명단에 보이는 인원과 반드시 같은 수**를 셉니다. 숫자를 누르면 그 조건 그대로
  학생명단이 열립니다. 성별이 비어 있는 학생은 남·여 어느 쪽에도 넣지 않고 따로 세며,
  주소는 '분류' 와 '미분류' 와 '주소 없음' 을 섞지 않습니다.
  집계를 저장해 두지 않고 볼 때마다 지금 자료를 셉니다. 지난 학년도를 고르면 그때의
  학년·반으로 셉니다.

- **파일 내보내기** — 조건에 맞는 학생을 골라 바로 Excel 명단을 만듭니다. 학생명단에서
  조건을 걸고 [내보내기] 를 누르면 그 조건이 그대로 넘어오고, 화면에 보이던 인원과
  파일에 들어가는 인원이 같습니다.
  - **사용자 지정 Excel** — 필요한 열만 골라 원하는 차례로. 고른 차례가 Excel 의 열
    차례가 됩니다.
  - **학교종이 학생명단** — 학급마다 시트 한 장(`1학년 가람반` · `4학년 1반`).
    보호자휴대폰1은 주보호자 → 모 → 부, 2는 1에 쓰이지 않은 번호를 넣어 **같은 번호를
    두 칸에 적지 않습니다.**
  - **알림e 문자서비스** — 이름 · 전화번호 · 비고. **비고는 빈칸으로 나갑니다**
    (열은 양식대로 그대로 있습니다). 전체 / 학년별 / 학년·반별 가운데 고른 단위로
    파일을 나누고, 한 파일이 1,000명을 넘으면 그 안에서만 나눕니다.
- 만들기 전에 **어떤 파일이 몇 개, 누가 빠지는지**를 먼저 보여 줍니다. 반이 없거나
  전화번호가 없어 빠지는 학생은 이름으로 알려 주고, 눌러서 바로 고칠 수 있습니다.
- 전화번호는 앞의 `0` 이 사라지지 않게, 주소는 입력한 원본 그대로 나갑니다.
  저장 위치는 저장 창(파일 하나)이나 폴더 창(여러 개)에서 직접 고릅니다.

- **학년도 전환** — 한 해가 끝나면 다음 학년도 명단을 만듭니다. **지난 학년도를 고치지
  않습니다.** 2026학년도 3-가람-7 은 그대로 두고 2027학년도 4-나리-12 를 새로 만들기 때문에
  지난 명단·통계를 언제든 그대로 다시 볼 수 있습니다.
  - [진급 배정 양식 받기] 로 1~5학년 명단을 Excel 로 받아 **새 반과 새 번호만** 채워 다시
    넣습니다. 프로그램이 반을 정하지 않습니다.
  - 새 번호를 비워 두면 그 반 학생을 **이름 가나다순으로 1번부터** 매깁니다. 일부만 채우면
    어느 반인지 알려 주고 멈춥니다 — 빈 자리를 채우면 의도한 배치가 깨지기 때문입니다.
  - 만들기 전에 **진급·졸업 인원, 학년별 이동, 새 학년도 학급별 남녀 인원, 학생별 변경**을
    모두 보여 줍니다. 새 반이 없거나 번호가 겹치는 학생은 이름으로 알려 주고 막습니다.
  - 적용 직전에 **자동으로 백업**을 만들고, 한 번에 처리합니다. 중간에 실패하면 하나도
    바뀌지 않습니다.
  - 6학년은 졸업 처리합니다. 사정이 있는 학생은 미리보기에서 졸업 대상에서 뺄 수 있고,
    프로그램이 임의로 7학년을 만들지 않습니다.
  - 새 1학년 신입생은 전환 뒤 가져오기 화면에서 넣습니다 — 주소 판정·중복 확인·형제 후보
    찾기가 평소와 똑같이 이루어집니다.
- **졸업생** — 졸업 학년도별로 졸업 당시 학년·반·번호를 그대로 봅니다. 졸업생은 현재 명단과
  통계에서 빠지지만 자료는 지우지 않습니다. 형제 관계도 남아 있고 `졸업` 으로 표시됩니다.
  잘못 처리했으면 [졸업 취소] 로 되돌릴 수 있고, 처리한 기록은 학적 이력에 남습니다.

## 진행 상황

| Phase | 내용 | 상태 |
|---|---|---|
| 0 | 프로젝트 골격 · DB 스키마 · 화면 셸 · 설정/학년도 | ✅ |

## 만드는 방법 (개발)

### 필요한 것

- [Node.js](https://nodejs.org) 20 이상
- [Rust](https://rustup.rs)
- Visual Studio Build Tools (C++ 데스크톱 개발)

### 실행

```bash
npm install
npm run app
```

### 실제 자료를 건드리지 않고 연습하기

```bash
npm run app:sandbox
```

자료를 `%APPDATA%\kr.school.studentroster.sandbox\` 에 따로 만들므로
실제 자료(`kr.school.studentroster`)는 손대지 않습니다. 창 제목에 **연습용**이라고 나옵니다.

### 연습용 자료 채우기

실제 학교 규모에서 화면을 확인할 때 씁니다. 생년월일 오타 · 빈 연락처 · 반 미정이
일부러 섞여 있어 '확인 필요' 흐름까지 볼 수 있습니다.

```bash
npm run seed
```

`npm run seed -- 300` 처럼 인원을 정할 수 있고, `npm run seed -- --reset` 은
연습용 학생을 모두 지우고 다시 채웁니다. 넣은 뒤 앱에서
**설정 → 자료 점검 → 확인 필요 다시 계산**을 한 번 누르면 표시가 만들어지고,
**설정 → 본교 형제 찾기 → 형제 후보 다시 찾기**를 누르면 형제 후보가 만들어집니다.

이름이 `○한별` `○두별` `○세별` 인 학생 19명은 형제 판정의 경계를 확인하려고 일부러
짜 둔 자료입니다. 네 항목이 모두 같은 남매, 형제 3명, 한 항목만 같은 남, 보호자 정보가
없는 학생, 이미 '형제 아님'으로 정해 둔 쌍 등이 들어 있습니다.

번호 재정렬은 `6학년 라온반`(1~23번이 가지런함), `4학년 라온반`(1,2,3,5,6,9 로 띄엄띄엄 +
번호 없는 학생), `2학년 라온반`(5번이 둘 — 자동 변경이 막혀야 함)에서 확인할 수 있습니다.

> 연습용 폴더에만 씁니다. 실제 자료는 건드리지 않습니다.

### 가져오기 시험용 엑셀 만들기

```bash
npm run sample
```

제목 줄 · 다른 열 이름 · 숫자 칸 생년월일 · 앞자리 0이 빠진 연락처가 섞인 1,200명짜리 파일을
`scratch/` 에 만듭니다. 학교에서 실제로 오는 파일과 비슷하게 일부러 지저분합니다.

```bash
npm run sample -- 1200 "scratch/수정본.xlsx" --changed
```

연락처를 바꾼 판을 만들어 **다시 가져오기**(기존 학생 갱신)를 시험할 수 있습니다.

### 검사

```bash
npm run build           # 타입 검사 + 화면 빌드
npm run check:model     # 화면 쪽 순수 함수 검사 (표시 형식·상태 배지)
cd src-tauri && cargo test --lib   # 서버 테스트 (정규화·검색·확인 필요)
```

### 구조

```
src/                 React 화면
  components/        AppShell(사이드바) · ui(Page/Card/Table/Drawer/Badge …)
  features/          화면별 덩어리 — student/ (등록 폼 · 상세 Drawer)
  ipc/               Rust 명령 호출 래퍼 (Rust commands/ 와 1:1)
  lib/               화면 쪽 순수 함수 (표시 형식 · 학년도)
  pages/             화면
src-tauri/
  migrations/        SQL 마이그레이션 (번호순, 배포 후 수정 금지)
  src/commands/      Tauri 명령 (입력 검증만)
  src/repo/          SQL (저장소 계층)
  src/domain/        순수 계산 규칙 (생년월일 · 연락처 · 주소 · 형제 · 번호 재정렬 …)
  src/import/        엑셀 가져오기 (읽기 · 짝짓기 · 분석 · 적용)
  src/export/        엑셀 내보내기 (양식 프리셋 · 파일 쓰기)
  src/transition/    학년도 전환 (배정 파일 읽기 · 계획 · 적용)
  src/job.rs         오래 걸리는 작업의 진행 상황 알림 (job://progress)
  src/db/            연결 · 마이그레이션 러너 · 백업/복원
docs/                설계안 · 운영안내
scripts/             아이콘 원본 · 버전 맞추기 · 연습용 자료 · 시험용 엑셀
```

규칙이 있는 계산은 모두 `src-tauri/src/domain` 에 두고 단위 테스트를 붙입니다.
화면은 보여 주기와 사용자 선택만 맡고, 저장되는 값은 언제나 Rust 가 만듭니다.

### 버전 올리기

```bash
npm run version:set 0.2.0
```

`package.json` · `tauri.conf.json` · `Cargo.toml` 세 곳을 한 번에 맞춥니다.

### 앱 아이콘

원본은 `scripts/appicon.png` 입니다. 바꿀 때는 그 파일을 갈아 끼우고:

```bash
npx tauri icon scripts/appicon.png
```

Windows 만 만들므로 생성된 `src-tauri/icons/android`, `ios` 폴더는 지웁니다.
